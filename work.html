The challenge

Making AI output usable beyond a demo. Models needed bounded tools, meaningful feedback, recoverable jobs, and a clear path from a creative decision to a reproducible edit. I worked across that path: model orchestration, compiler validation, browser previews, native rendering, revision history and deployment.

One principle runs through the system: models make bounded creative decisions; application code owns authorization, state, geometry, timing and persistence. No agent has direct database access.

Underneath it is a typed composition layer I designed: a graph of media, perception and composition with versioned schemas and pinned evidence, which the editor, agents and renderer all read the same way.

Ingest and transcription

Model decides

No model decision. Speech recognition runs as its own durable job.

Software guarantees

Uploads are transcoded and transcribed as durable jobs. An agent that needs a transcript can defer, release its worker claim and resume when the transcription finishes.

Multimodal clip selection

Model decides

Fast: one model round discovers, constructs and scores clips. Deep: one multimodal judgement per shortlisted region.

Software guarantees

Transcript boundaries and cheap audio-visual cues propose regions; software merges and prunes them, routes optional analysis by speech density and cut rate, ranks deterministically, and reuses completed stages keyed by input hashes.

Specialist agents

Model decides

Caption Director plans narrative roles and emphasis; Caption Design Agent writes motion themes; Music Agent chooses an eligible track and window, or none; RAVA Director picks subjects and framing.

Software guarantees

Typed tools with strict validation, step and call budgets, durable checkpoints, a motion compiler, perceptibility and diversity checks, and deterministic crop, timing and gain.

Revision-safe authoring

Model decides

Agents only propose typed edit commands.

Software guarantees

The authoring gateway checks the expected revision and stable command ID, locks resources, validates pinned dependencies and writes revision and receipt atomically. Stale edits are rejected; an identical retry returns the original receipt.

Model decides

No model decision.

Software guarantees

Caption motion is evaluated in TypeScript for the browser preview and in Python for native export, held to the same results by a shared fixture protocol (within 1e−6). Geometry checks reject motion that leaves the frame.

Publishing and integrations

Model decides

No model decision.

Software guarantees

An immutable publishing intent fans out into one job per destination with its own state. An uncertain upload is marked ambiguous and reconciled instead of retried blindly. OAuth connections, capability checks, history import and analytics per provider.

Read the case study

Underneath every stage: a typed composition graph with versioned schemas and pinned evidence (read more), a PostgreSQL job queue (atomic claims with FOR UPDATE SKIP LOCKED, leases, heartbeats), separate AWS ECS worker pools for general and reframing work, metered model routes, and a CI release pipeline with migrations, readiness and smoke checks.

Case studies

  1. A typed foundation for media, perception and compositionThe composition layer: a typed property graph with versioned schemas, three-valued validation, pinned evidence and exact time — the model agents, editor and renderer share.
  2. Agents inside an editable media systemFour specialist agents — caption direction, caption design, music, reframing — with bounded tools, durable checkpoints and recovery that never re-asks the model.
  3. A language and compiler for caption motionA typed motion language, a compiler into the editor’s caption engine, a repair loop for generated themes, and one motion model shared by preview and export.
  4. Multimodal selection and reframingFast and Deep clip selection that controls inference depth, and reframing where a multimodal model chooses subjects and code computes the camera.
  5. Authoring, orchestration and infrastructureOne accepted revision history for human and AI edits, durable job execution on AWS, metered model operations, and publishing that is safe to retry.

Research method

The strongest engineering came from failures in real execution, each with an implemented consequence:

  • Provider schema limits changed the agent protocol to a small decision envelope with locally validated arguments.
  • Imperceptible motion led to deterministic amplitude and duration checks on generated themes.
  • Repetitive themes led to motion-graph comparison between variants.
  • Preview/export mismatches led to evaluator and layout fixes across the TypeScript and Python renderers.
  • Expensive selection retries led to durable stage reuse keyed by input hashes.
