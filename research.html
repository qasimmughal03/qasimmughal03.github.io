Enterprise RAG evaluation

Retrieval · PostgreSQL, pgvector, Python

A retrieval service built entirely on PostgreSQL: HNSW vector search with pgvector, full-text search, reciprocal rank fusion and optional cross-encoder reranking, with tenant-level access control enforced in the database.

I evaluated it on BEIR SciFact (all 300 test queries) with paired significance tests. Dense and hybrid retrieval performed similarly (nDCG@10 ≈ 0.70). Cross-encoder reranking added no statistically significant gain (p = 0.73) on CPU while raising tail latency by more than two orders of magnitude. The evaluation also exposed a full-text configuration that returned no results for most long queries, which I traced to conjunctive query parsing and fixed.

GQL-Core

Graph querying and reasoning · Python · alpha

An embedded, in-memory property-graph engine with a Cypher-inspired query language, a typed query-plan API that LLM agents can build and validate without generating query text, and declarative inference rules (subtype, inverse, symmetric, transitive, composition) with provenance.

Voice AI patient registration

Voice agent · Vapi, Gemini, FastAPI, PostgreSQL

A phone-callable intake agent that registers patients and books appointments through natural conversation, deployed with a public REST API. The agent’s tool calls and the REST API construct the same validation models, so a value the model gets wrong is rejected exactly as a bad API request would be.

Medical image anomaly detection

Final-year project · PyTorch

A VQ-VAE-based detector for lung and breast imaging that combines global and local reconstruction error with latent-space Mahalanobis distance, and produces heatmaps to localise anomalies. Academic research; not a clinically validated system.
